# Synthetic / Proxy / Controlled-Stress Artifact System Audit

**Date:** 2026-06-02

This audit answers one question: how much of the current ELARA paper/system uses
synthetic, pseudo, proxy, generated, or controlled-stress material?

The answer is not one number. The repository uses these constructs in four
different scientific roles:

1. **Synthetic raw dataset evidence:** a dataset whose images/views are
   synthetic rather than captured from a physical scene.
2. **Derived or pseudo modalities:** real data where one "modality" is computed
   from another view or reconstructed rather than independently sensed.
3. **Controlled stress/degradation protocols:** real scores/data deliberately
   corrupted to test mechanism behavior.
4. **Synthetic code/test scaffolds:** fallback loaders, unit-test arrays, and
   generative notebooks that should not carry paper claims.

## Claim-Bearing Synthetic / Proxy / Stress Objects

These are the actual scientific objects, not every per-seed output file.

### 1. Synthetic Raw Dataset

**Eyecandies** is explicitly synthetic RGB-D-normal data. It is not used to make
an official positive transfer claim because Family D failed:

- D-EYE-1 primary ensemble delta AUC = -0.0010, CI crosses zero.
- D-EYE-2 primary ensemble delta AUC = -0.0109, CI crosses zero.

Risk: reviewers can object if Eyecandies is framed as real industrial transfer.
Current framing is safe only if it remains "failed/development/negative evidence."

### 2. Derived Proxy Modalities

**VisA RGB+edge** and **MVTec LOCO-AD RGB+edge** create an edge proxy from the
same RGB image. The second view is useful as a diagnostic but cannot prove
independent multimodal generalization.

Key code:

- `src/scripts/prepare_visa_fusion_benchmark.py`
- `src/scripts/prepare_mvtec_loco_fusion_benchmark.py`
- `src/scripts/derive_noise_floor_csv.py`

Risk: these results must stay bounded as proxy-view diagnostics.

### 3. Label-Aligned Composite Benchmark

The ELARA-Bench-LA style benchmark aligns separate tabular/text domains by
label rather than naturally co-observed incidents.

Risk: it is valid for mechanism and stress testing, but not for a natural
multimodal incident claim.

### 4. Controlled Score-Corruption / Stress Protocols

The system repeatedly uses controlled stress to test whether reliability gating
stops trusting bad evidence:

- `zero_attack`
- `max_attack`
- `gaussian_noise`
- k-of-D corruption sweeps
- missing-domain/dropout sweeps
- alpha degradation sweep: score blended toward uniform noise
- category-mixture-shift stress
- VisA edge-proxy noise-floor counterfactual
- gradient/adversarial stress artifacts

These are useful and scientifically legitimate when called "controlled stress"
or "mechanism evidence." They do not count as natural degradation or production
readiness.

### 5. Natural Degradation Boundary

Real-IAD D3 is not treated as synthetic degradation in the D16 claim. It is a
natural-degradation/headroom audit using pseudo-3D/point-cloud views. Current
official result:

- stress subset vs CW: positive point estimate but CI crosses zero, fail
- clean subset vs CW: no regression, pass
- all-test vs CW: positive, supportive only
- all-test vs SAR: negative, fail

So D16 helps the paper because it replaces a purely synthetic-stress criticism
with natural-degradation evidence, but it still does not pass the strict gate.

## Final Classification

The system is **not mostly synthetic**. The main datasets are real, but a
large part of the current claim structure is **controlled stress, proxy-view,
or mechanism evidence**.

The honest claim boundary is:

- Strongest acceptable phrase: "bounded reliability-stress mechanism validated
  on real and controlled-stress benchmarks, with natural-degradation evidence
  that is supportive but not gate-passing."
- Unsafe phrase: "universal production-ready multimodal anomaly detection."
- Unsafe phrase: "strict natural positive transfer is confirmed."
- Unsafe phrase: "derived edge-proxy results prove independent multimodal
  generalization."

## Required Cleanup / Guardrails

1. Keep Eyecandies as synthetic failed/development evidence.
2. Keep VisA/LOCO edge results as derived-proxy diagnostics.
3. Keep ELARA-Bench-LA as label-aligned mechanism/stress evidence.
4. Keep D16 Real-IAD D3 as natural-degradation evidence, but not a passed gate.
5. Keep `load_paysim.py` synthetic fallback default-off.
6. Add or maintain tests proving production/research runs cannot silently use
   synthetic fallback.
7. Ignore or remove `._*` sidecars so future audits are not contaminated.
