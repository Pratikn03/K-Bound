# ELARA Research Dashboard

JavaScript front-end + C++17 snapshot aggregator for AutoML Flagship V8 research metrics, gates, and checklist progress. Replaces the orphan Streamlit `dashboard/` UI for research status (Streamlit components are not used here).

## Layout

```
research_dashboard/
├── CMakeLists.txt
├── build.sh
├── cpp/
│   ├── main.cpp              # elara_research_snapshot
│   └── third_party/
│       └── nlohmann/json.hpp  # vendored single-header
└── web/
    ├── index.html
    ├── app.js
    ├── styles.css
    └── data/snapshot.json    # generated by C++ tool
```

## Data sources (repo root relative)

| File | Used for |
|------|----------|
| `elara_master_c/audits/checklist_progress.json` | Checklist %, items by stage, blockers, gate item status |
| `elara_master_c/audits/confirmatory_statistics_report.json` | M1/M2 deltas, bootstrap CIs, gate D/E flags |
| `elara_master_c/audits/python_file_catalog.json` | Python codebase usage summary |
| `research_lock/FLAGSHIP_DEV_PROTOCOL_v1.yaml` | Protocol version, status, confirmatory stop rule |

## Build C++ aggregator

Requires **CMake 3.14+** and a C++17 compiler. If `cmake` is missing, `build.sh` falls back to direct `clang++` compilation.

```bash
cd research_dashboard
chmod +x build.sh
./build.sh
```

Or manually:

```bash
cd research_dashboard
mkdir -p build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
cmake --build . -j
```

## Generate snapshot JSON

From the **repo root** (or pass `--repo-root`):

```bash
./research_dashboard/build/elara_research_snapshot \
  --repo-root /Volumes/T9/uav/AutoML_Flagship_V8
```

Default output: `research_dashboard/web/data/snapshot.json`

Options:

- `--repo-root PATH` — AutoML_Flagship_V8 root (auto-detected if omitted when cwd is inside repo)
- `--output PATH` — custom snapshot path

## View dashboard

Serve the static `web/` folder (fetch requires HTTP, not `file://`):

```bash
cd research_dashboard/web
python3 -m http.server 8765
```

Open http://localhost:8765/research_dashboard/web/

The UI includes **Home**, **Analytics**, **Gates**, **Confirmatory**, **Research profile**, **Codebase**, and **Settings** (sidebar navigation, clickable gate cards, profile saved in browser).

Refresh after re-running the C++ tool to pick up new audit JSON.

**Recommended:** serve from **repo root** (enables gate drill-down JSON fetch):

```bash
chmod +x research_dashboard/serve.sh
./research_dashboard/serve.sh 8765
# → http://localhost:8765/research_dashboard/web/?live=1
```

## Live refresh

**File watcher** (polls audit JSON every 2s, rebuilds snapshot):

```bash
chmod +x research_dashboard/scripts/watch_audits.py
python3 research_dashboard/scripts/watch_audits.py
```

In another terminal, run `./research_dashboard/serve.sh` and enable **Live refresh** in the UI (or `?live=1`).

**Cron** (example every 15 min):

```bash
chmod +x research_dashboard/scripts/cron_refresh.sh
# crontab -e:
# */15 * * * * /path/to/AutoML_Flagship_V8/research_dashboard/scripts/cron_refresh.sh
```

## Charts, diff, drill-down

- **Chart.js** — checklist/execution trend (`history_timeline`), confirmatory Δ bars, stacked stage completion
- **Diff** — `diff_vs_previous` vs last file in `web/data/history/`
- **Gate drill-down** — click a gate card; fetches evidence JSON via repo-root HTTP server
- **History** — each aggregator run appends `web/data/history/snapshot_YYYYMMDDTHHMMSSZ.json` (pruned to 100 by default)

Aggregator flags: `--history-dir`, `--max-history N`, `--no-history`

## CI

Workflow `.github/workflows/research_dashboard.yml` builds the aggregator, writes `snapshot.json` + history, uploads artifacts on audit changes.

## Metrics shown

- **Verdict** — execution vs scientific readiness from checklist summary
- **Checklist** — done/total, execution %, per-stage breakdown (T0–T7, GATE, LOG)
- **Gates A–F** — pass/fail from checklist gate items (+ Gate F scientific)
- **Confirmatory** — M1/M2/M2_external cell deltas, 95% bootstrap CIs, gate D/E per cell
- **Blockers** — remaining checklist blockers (RGA+, Gate D/E/F scientific)
- **Python catalog** — total/used/unused files and category breakdown
- **Protocol** — FLAGSHIP_DEV_PROTOCOL_v1 metadata
